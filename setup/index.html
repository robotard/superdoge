What this page is: a step-by-step launch guide. Your existing homepage stays at the root. This guide is a separate page at /setup/. The bot files live in /bot/ and deploy as a separate Cloudflare Worker.

1 · Create the Telegram bot

In Telegram, message @BotFather. Send /newbot, choose a name such as Super Doge, then choose a username ending in bot. Save the token privately; never put it in GitHub.

2 · Create the group

In Telegram, create a group such as Super Doge Community. Add your bot as a member. Keep Telegram's default group privacy on; it can respond to commands and welcome messages without reading ordinary chat.

Part A · Add the files to GitHub

  1. Open robotard/superdoge and add the supplied setup/index.html and bot/ folder. Keep the current root index.html; this guide is a new subpage.
  2. Once Cloudflare Pages finishes its normal GitHub deployment, open https://superdoge.co/setup/. If your Pages project uses a custom build-output folder, place setup/index.html inside that published folder instead.
  3. From the repo folder, sign in with npx wrangler login. Then create a D1 database for the address list. It prints an ID; copy that ID into bot/wrangler.jsonc in place of REPLACE_WITH_D1_DATABASE_ID. The config already connects that database to the Worker as DB.
npx wrangler login
npx wrangler d1 create superdoge-airdrop

The D1 database holds the submitted wallet addresses until the configured deletion date. You can use Cloudflare’s terminal or your own Mac Terminal with Node.js available.

Part B · Connect the Worker

  1. In Cloudflare, go to Workers & Pages → Create → Worker. Connect the same GitHub repo. Set the Worker root directory to bot and the deploy command to npx wrangler deploy. Name the Worker superdoge-airdrop-bot.
  2. Set these runtime variables in the Worker’s Settings → Variables and Secrets area. Use UTC timestamps in ISO format. Get your numeric Telegram ID from @userinfobot.

Variables

  • BOT_USERNAME — bot username, without @
  • ADMIN_TELEGRAM_ID — your numeric Telegram ID
  • AIRDROP_CLOSES_AT — e.g. 2026-12-31T23:59:00Z
  • AIRDROP_DELETE_AFTER — later UTC date, e.g. 2027-01-31T23:59:00Z

Encrypted secrets

  • TELEGRAM_BOT_TOKEN — the token from BotFather
  • TELEGRAM_WEBHOOK_SECRET — make a long random value, such as output from openssl rand -hex 32

Use Cloudflare’s secret fields. Never commit these values to GitHub or put them in this HTML page.

  1. Apply the supplied database migration from the repo folder, then deploy the Worker once. Cloudflare Git builds can handle later updates from GitHub pushes.
npx wrangler d1 migrations apply superdoge-airdrop --remote --config bot/wrangler.jsonc
npx wrangler deploy --config bot/wrangler.jsonc

Visit the Worker’s /health address once it is deployed; it should say Super Doge bot is ready.

Part C · Point Telegram at the Worker

Telegram sends bot updates to the Worker using a webhook. In Terminal, paste this block, replacing the three values. Use the exact webhook secret saved in Cloudflare.

read -s "TG_TOKEN?Paste BotFather token: "; echo
read -s "HOOK_SECRET?Paste webhook secret: "; echo
WORKER_URL="https://superdoge-airdrop-bot.YOUR-SUBDOMAIN.workers.dev"
curl -sS -X POST "https://api.telegram.org/bot${TG_TOKEN}/setWebhook" \\
  --data-urlencode "url=${WORKER_URL}/telegram" \\
  --data-urlencode "secret_token=${HOOK_SECRET}"
unset TG_TOKEN HOOK_SECRET

Replace YOUR-SUBDOMAIN with the Cloudflare Workers URL shown on your Worker page. The token is entered silently in Terminal and is not part of the copied repo files.

Part D · Set up the group

  1. In @BotFather, use /setjoingroups to allow the bot in groups. Leave privacy mode enabled for this info-and-welcome setup.
  2. Add the bot to Super Doge Community. Make it a group admin only if you want it to moderate or manage group settings; basic welcomes and slash-command replies need fewer permissions.
  3. In BotFather, use /setcommands and enter:
    start - Welcome and Super Doge links
info - Super Doge project information
airdrop - Private temporary airdrop registration
cancel - Cancel wallet registration
export - Close intake and send admin CSV
  4. Test in the group with /start, /info, and /airdrop. Then open a private chat with the bot and use /airdrop to test address intake. Never test with a real seed phrase or private key.
Keep addresses private. The bot directs group members to private chat for registration. It does not verify wallet ownership or promise eligibility or an airdrop allocation.

How to run the airdrop batch

  1. Before the closing time, review your published eligibility rules and privacy wording.
  2. As the configured admin, send /export to the bot in a private chat. This closes registration and sends a CSV of unique wallets to that admin Telegram account.
  3. Use the CSV with your distribution process. The Worker deletes its D1 entries after the configured deletion time; delete the CSV message/download and any other copies after distribution too.
Before inviting the public: replace the example dates, publish your actual eligibility and privacy details, confirm the Worker has a D1 binding and webhook, and test with a throwaway wallet. Telegram may retain the exported document in the admin chat until you delete it.
